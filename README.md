# Поиск товара по фото (CLIP, офлайн)

## Файлы
- `product-search.js` — модуль: строит эмбеддинги CLIP для каталога, ищет похожие по фото. Кладёшь рядом с остальными скриптами PWA.
- `product-search-demo.html` — готовая страница для проверки/встраивания. Использует CSV-публикацию Google-листа как источник — если у PWA уже есть свой синк данных из таблицы, лучше не тянуть CSV отдельно, а передать уже загруженные строки в `buildIndex()` напрямую (см. ниже).

## Как это работает
1. Модель CLIP (`Xenova/clip-vit-base-patch32`) грузится в браузере через `transformers.js`, работает на WASM — не нужен сервер и не нужен Android-нативный код.
2. Для каждого фото в J/K считается вектор-эмбеддинг и кладётся в IndexedDB (кэш в браузере, переживает перезагрузку страницы).
3. При фото с камеры телефона считается такой же вектор и сравнивается косинусной близостью со всеми сохранёнными — топ-5 с наибольшим совпадением и есть найденный товар (код из колонки D).
4. Повторная индексация не пересчитывает уже обработанные ссылки — можно звать `buildIndex()` при каждом заходе в раздел, будут докачаны только новые/изменённые товары.

## Встраивание в существующую логику синка
Если данные с листа уже приходят в виде массива объектов (как в текущей PWA), просто адаптируй под формат `{code, images}`:

```js
import { buildIndex, findSimilar } from './product-search.js';

const products = existingSyncedRows.map(row => ({
  code: row.D,                       // или как называется поле у тебя
  images: [row.J, row.K].filter(Boolean),
}));

await buildIndex(products);
```

## Важное ограничение — CORS
`product-search.js` качает картинки напрямую по ссылкам из J/K через `fetch`. Если хостинг фото не отдаёт заголовок `Access-Control-Allow-Origin`, конкретная ссылка не проиндексируется (в консоли будет warning, весь процесс не упадёт). Если это массово случится — покажи мне, откуда ссылки (домен), решим через прокси на твоём Apps Script backend.

## Размер и производительность
- Модель: ~90 МБ при первой загрузке, дальше кэшируется браузером (Cache Storage), офлайн-повторный заход не тянет её заново.
- Один эмбеддинг ≈ 2 КБ в IndexedDB — каталог на несколько тысяч фото не проблема.
- Индексация тысячи фото в браузере на телефоне — по опыту таких сеток, порядка 10–20 минут при первом построении; дальше только дельта.
